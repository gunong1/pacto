# 배포 후 실제 AI 분석 검증 절차 (실기기)

실제 AI 분석은 아직 검증되지 않았습니다. 아래를 마치기 전에는 "완료"로 보지 않습니다.
계약서는 **PACTO 테스트용 가상 계약서**(자동차 장기렌트, 가상 정보)만 사용합니다. 실제 계약서를 쓰지 않습니다.

## 준비
- 배포 계획(DEPLOY_PLAN.md) 1~3단계 완료 · 새 APK 설치
- 테스트용 새 계정 (기존 데이터와 섞이지 않게)
- MY → 내 계약자 정보: 처음에는 **비워 둠** (A 단계), B 단계에서 "김도윤" 등록

## A. 업로드 → 보호 → 분석
1. + → PDF → 가상 장기렌트 계약서 선택
2. 보호 단계: 주민번호·카드·계좌·연락처·이메일이 가려졌다는 안내가 나오는지 (원문이 화면에 보이면 중단)
3. 분석 완료 후 확인 화면

## B. 확인 화면 체크
| # | 확인할 것 | 기대 |
|---|---|---|
| B1 | 계약 당사자 | 렌탈회사(임대인) = 주식회사 팩토렌터카 · 고객(임차인) = 김도윤 · "확인 필요" 없음 |
| B2 | 대표자 | 대표자 = 박지훈 (렌탈회사 이름에 섞이지 않음) |
| B3 | 근거 | 당사자 칸의 근거 아이콘 → 계약서 문장 (민감정보는 가려진 상태) |
| B4 | 이 계약에서 누구세요? | 추천: 고객(임차인) — 아직 확정 아님 · 금액은 "방향 확인 필요" |
| B5 | 금액 | 보증금 5,000,000(10/20) · 월 렌트료 649,000(매월 20일) · 초기 등록대행비 120,000(10/20) · 탁송비 70,000은 "선택" |
| B6 | 지급자 | (확인 방법) 저장 후 아래 SQL의 payer_role = customer(월 렌트료) |

## C. 역할 확인 → 합계
| # | 동작 | 기대 |
|---|---|---|
| C1 | 역할 확인 없이 저장 → 홈 | 10월 출금 ₩0 + "계약 금액 5,769,000원의 입출금 방향을 확인해주세요" + 추천 고객(임차인)·김도윤 [맞아요] |
| C2 | [맞아요] | 10월 총 출금 ₩5,769,000 = 일반 769,000 + 보증금 5,000,000 |
| C3 | 캘린더 11월 | 총 출금 ₩649,000 (탁송비 없음) |
| C4 | 계약 수정 → 변경 → 렌탈회사(임대인) | 미리보기 "출금 → 입금" → 적용·저장 → 홈 출금 0 · 입금 5,769,000 |
| C5 | 다시 고객으로 | 원래대로 5,769,000 출금 |
| C6 | MY에 "박지훈"(대표자) 등록 후 새로 등록 | 렌탈회사로 추천하지 않음 (대표자는 돈을 내고 받는 쪽 아님) |
| C7 | MY에 "김도윤" 등록 후 새로 등록 | 추천: 고객(임차인) — 등록한 이름과 같아요 |

## D. 기존 계약 (배포 전 등록해 둔 장기렌트)
| # | 기대 |
|---|---|
| D1 | 렌탈회사·고객 칸이 자동으로 채워짐. 직접 입력한 이름이 계약서 이름과 **표기만** 다르면 입력한 이름 유지 |
| D2 | 실제로 다른 이름이면 수정 화면에 "렌탈회사 이름이 두 가지예요" 카드 — 두 후보 중 선택 |
| D3 | 역할을 확인한 적이 없으면 홈에 [맞아요] 카드, 확인하면 합계 반영 |

## E. 알림
- 결제 알림: 역할 확인 전에는 "내는 돈인지 받는 돈인지 확인해주세요", 확인 후 "결제일입니다"

## 확인용 SQL (대시보드 SQL Editor — 읽기만, 계약서 원문·개인정보를 출력하지 않음)
```sql
-- 최근 분석 지시문 버전 (extract-v17 이어야 함)
select prompt_version, status, created_at from analysis_jobs order by created_at desc limit 3;
-- 테스트 계약의 결제 방향·지급자 (금액·이름만)
select p.label, p.amount, p.direction, p.direction_basis, p.payer_role, p.payee_role, p.money_nature
from contract_payments p join contracts c on c.id = p.contract_id
where c.title like '%장기렌트%' order by c.created_at desc, p.sort_order limit 10;
-- 당사자 역할 (이름은 가상)
select jsonb_path_query_array(parties, '$[*].role') as roles, user_party_role from contracts where title like '%장기렌트%' order by created_at desc limit 1;
```

결과(스크린샷 또는 위 표의 통과/실패)를 공유해 주시면 실제 추출값과 기대값을 비교해 보고합니다.
