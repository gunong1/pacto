## 2. 발견한 취약점 (P1) — 문서 파일 경로를 남의 폴더로 기록할 수 있음

- 원인: `contract_documents.storage_path`는 앱이 직접 기록하는 값인데 형식 검사가 없었다. RLS는 행의 `user_id`만 본인인지 확인한다.
  B가 `"{B id}/../{A id}/..."` 또는 A의 보호본 경로(`{A id}/{문서 id}.protected_view.pdf`)를 자기 문서 경로로 기록할 수 있었다 (step35에서 재현).
- 영향: 서버 함수는 관리자 권한으로 이 경로의 파일을 다룬다.
  - protect-document: 그 파일을 내려받아 B의 보호본을 만든다 → B가 A의 계약 내용을 볼 수 있음.
  - cleanup-orphans: 24시간 뒤 그 경로 파일을 지운다 → A의 파일 삭제 가능.
- 전제: A의 사용자 id(UUID)와 문서 id를 알아야 한다 (추측으로 알기는 매우 어려움). 운영에서 실제로 악용됐는지는 **알 수 없음** (점검 SQL로 형식 위반 행 수 확인 가능).
- 수정 (로컬 적용·검증, 운영 미적용):
  1. DB 제약 `20261102000001_document_path_owner.sql`: 경로 = `{user_id}/{파일 이름}`, 하위 폴더·`..` 금지 (contract_documents, document_derivatives). 추가만 — 기존 데이터·정책·함수 변경 없음. 형식에 맞지 않는 기존 행이 있으면 적용 자체가 실패(데이터 안 바뀜).
  2. 서버 함수 방어선: protect-document·analyze-contract는 본인 폴더 경로만 내려받는다 (`downloadOwnObject`).
- 적용 전 점검: `scripts/deploy/inspect-document-paths.sql` (읽기 전용, 개수만 출력).

## 3. 앱 잠금

- 위치: MY > 보안 > 앱 잠금 — "지문·얼굴인식 또는 기기 잠금으로 PACTO를 보호합니다." (선택, 기본 꺼짐)
- 방식: OS 인증(`expo-local-authentication`) — 지문·얼굴인식, 안 되면 기기 PIN·패턴·비밀번호. PACTO 자체 PIN 없음, 생체 정보 저장·전송 없음, 서버 로그인과 무관.
- 켜기·끄기·잠금 시점 변경: 기기 인증 성공 시에만. 취소·실패면 그대로.
- 기기에 화면 잠금이 없으면 켤 수 없고 "기기 설정 열기"로 안내.
- 잠금 시점: 앱 시작(프로세스 재시작 포함) 항상 잠금 / 다른 앱에 다녀오면 **즉시(기본)** 또는 **1분 후**.
- 잠금 중에는 계약 화면을 그리지 않는다: 위에 덮는 방식이 아니라 화면 영역을 숨김(`display: none` + 보조기기 제외). 화면 상태는 유지되어 해제하면 보던 화면·푸시로 연 계약으로 이어진다.
  - 참고: 숨긴 영역의 화면 구조(웹 DOM)는 메모리에 남아 있다. 화면·보조기기에는 나오지 않음(E2E F). 더 엄격하게(해제 전 아예 만들지 않기) 바꿀 수 있으나 푸시 진입·입력 중 내용 유지가 어려워져 이번에는 숨김 방식으로 했다.
- 푸시·딥링크로 열어도 잠금이 먼저 (E2E F). Android 뒤로 가기는 잠금 화면에서 막음.
- 자동 인증은 잠금 화면이 뜰 때 1번만. 취소하면 다시 띄우지 않음(반복 없음).
- 인증 창(기기 PIN 화면)으로 잠시 나갔다 오는 것, 사용자가 연 사진 선택·카메라·파일 선택·권한 창·문서 브라우저(5분 이내)는 잠그지 않음.
- 설정을 읽지 못하면 잠근다(fail-closed). 잠금 화면에는 항상 "로그아웃하고 다시 로그인"이 있어 영구히 갇히지 않는다. 로그아웃·탈퇴하면 이 기기의 잠금 설정을 지운다.

## 4. 백그라운드 화면 보호 (앱 잠금을 켰을 때만)

- Android: `FLAG_SECURE` (최근 앱 화면에 내용 안 보임 + 화면 캡처·녹화 차단). 범위: 앱 전체 · 앱 잠금 켰을 때만.
- iOS: 앱 전환 화면 흐림 처리 + 화면 캡처 제한. (iOS 빌드는 아직 없음 — 미검증)
- 잠금을 꺼 두면 기존과 같다 (캡처 가능).
